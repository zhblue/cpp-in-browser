双击行号或按 Ctrl+B 增删断点；停住时把鼠标放到变量名上能看它的当前值。「每行停留」是执行每行源码额外等的时间，默认 0.2 s，嫌慢就选 10⁻¹/10⁻²。调试构建固定 -O0，行号才不会被优化打乱；调试不设运行超时，暂停和降速的时间也都不计进「运行耗时」；正在运行的行跑出视野时编辑器会自动滚过去。调试依赖 SharedArrayBuffer，只有 https 或本机 http://localhost / 127.0.0.1 打开才有，且文档要带 COOP/COEP 响应头；http://公网域名 加满头也拿不到。BGM 把当前执行行的个位弹成音符（1=中音 do，2..7=re mi fa sol la si，8/9/0 往高八度走），不要听就取消勾选。每执行一行源码，左边那栏的「热力」就把这一行的背景加红一档（按次数取 log2，最重只到不吃字的程度），退出调试后红色保留着，用来找程序里最值得优化的位置；没停住时把鼠标放到红行上能看到确切次数

已知限制
  • 工具链是 LLVM 8 年代的 clang + libc++（不是 GCC/libstdc++）。<bits/stdc++.h> 由本页在 sysroot 解包后补一个虚拟头实现，清单只收录实测能过的头：<csetjmp> <csignal>、并发头、<filesystem> <regex> 都不在里面。C++20 的 <concepts> <ranges> <format> <coroutine> 不存在。
  • 文件系统是空的内存 FS：std::filesystem 基本不可用，没有真实磁盘。
  • std::thread 需要 SharedArrayBuffer + 跨源隔离，而且这份 sysroot 没链 pthread：即使页面开了隔离，多线程也多半停在链接期未定义符号。单线程程序不受影响。
  • 超时靠 worker.terminate() 实现，能杀掉死循环，但拿不到精确 CPU 时间。
  • wasm 线性内存无法由宿主设上限；超分会以 memory access out of bounds 报出。
  • system()、fork()、管道一类进程 API 不存在。
  • 调试构建固定 -O0（优化会把语句合并、行边界打乱），并且只给用户自己这份源文件里的行插桩：STL 内部下不了断点。降速的亚毫秒档位是按行累计后取整到 1 ms 睡的，不是单行精确计时。悬停看变量值只覆盖 POD（整型、浮点、指针、bool、char）；std::string、容器、结构体只报名字不展开内容，指针也只显示线性内存地址而不追字符串。变量按「声明行 ≤ 当前行」判定可见，块作用域结束后仍可能被列出来，值是它最后一次被写入的那份。
