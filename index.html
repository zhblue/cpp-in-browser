已知限制
  • 工具链是 LLVM 8 年代的 clang + libc++（不是 GCC/libstdc++）。<bits/stdc++.h> 由本页在 sysroot 解包后补一个虚拟头实现，清单只收录实测能过的头：<csetjmp> <csignal>、并发头、<filesystem> <regex> 都不在里面。C++20 的 <concepts> <ranges> <format> <coroutine> 不存在。
  • 文件系统是空的内存 FS：std::filesystem 基本不可用，没有真实磁盘。
  • std::thread 需要 SharedArrayBuffer + 跨源隔离，而且这份 sysroot 没链 pthread：即使页面开了隔离，多线程也多半停在链接期未定义符号。单线程程序不受影响。
  • 超时靠 worker.terminate() 实现，能杀掉死循环，但拿不到精确 CPU 时间。
  • wasm 线性内存无法由宿主设上限；超分会以 memory access out of bounds 报出。
  • system()、fork()、管道一类进程 API 不存在。
  • 调试构建固定 -O0（优化会把语句合并、行边界打乱），并且只给用户自己这份源文件里的行插桩：STL 内部下不了断点。降速的亚毫秒档位是按行累计后取整到 1 ms 睡的，不是单行精确计时。悬停看变量值覆盖 POD（整型、浮点、指针、bool、char）和定长数组（int a[30]、double m[4][4] 这类，元素是标量或指针时铺开前 50 个，多维按行优先摊平；char s[n] 整段都是可显示文字时直接写成 "hello" 一句，按第一个 0 收尾，掺了控制字符或非法 UTF-8 才退回逐个元素报数）；std::string、容器、结构体（以及元素是结构体的数组）只报名字不展开内容，指针也只显示线性内存地址而不追字符串，int a[] 形参和变长数组没有长度信息、同样只显示地址。观察窗收的是表达式，但求值器只读内存、不执行代码：a[i] a[10] m[1][2] *p p[i] &x a+j、四则/比较/逻辑/位运算、三元、类型转换都能算（值由主线程按 __pg_addr 登记的栈槽地址直接读共享内存，和悬停用的是同一份数据）；成员访问（s.x、p->v）、函数调用（v.size()）、全局变量（插桩只收 llvm.dbg.declare 覆盖的局部变量）、字符串字面量、++/--、sizeof 都算不了，会直接把原因写在那一行。下标越界不检查（C++ 本来也不检查），读到的是相邻内存。变量按「声明行 ≤ 当前行」判定可见，块作用域结束后仍可能被列出来，值是它最后一次被写入的那份。条件、循环体、自增全写在同一行的 for，整趟循环只触发行桩一次（热力停在最浅档、按一次「下一行」就走完），循环体另起一行才准。
